Como funciona cada etapa

Beat

Agendador Celery (único processo). A cada ~90s publica um job em lote no broker — não consulta CoinGecko nem calcula indicadores. Só dispara o ciclo.

Fila Valkey

Valkey como broker da fila Celery. Guarda a mensagem até o Worker consumir. As bolinhas no desenho representam as moedas do lote (bitcoin, ethereum, solana) a caminho do processamento.

Worker

Processo Celery que consome a fila. No ciclo atual faz 1 chamada CoinGecko em lote e em seguida roda o pipeline para cada moeda, de forma assíncrona (fora do request do browser).

pipeline

Código único (pipeline.py + indicators.py): cotação → grava série ZSET → calcula média móvel e volatilidade → grava cache STRING+TTL. Usado pelo Worker e também no MISS do BFF.

Fluxo: Beat agenda → Fila Valkey segura → Worker puxa → pipeline calcula → cards leem o cache (HIT).

Como ler o log

Dois caminhos

  1. Reativo (você abriu a página) — bff + valkey_cache. HIT = respondeu do cache. MISS = lote CoinGecko + pipeline.
  2. Proativo (a cada ~90s) — beat → valkey_broker → worker → pipeline. Depois o BFF tende a HIT.
